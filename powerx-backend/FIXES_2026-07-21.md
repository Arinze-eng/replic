This round hardens the agent's core behaviour and fixes the concrete bugs you

## 1 & 2 — Plan-first + auto tool detection/install (Manus-style)
**File:** `prompts/agent_system_prompt.md`

Added a **TOP-PRIORITY OPERATING CONTRACT** at the very top of the system prompt
(above everything else). On EVERY non-trivial task the agent now MUST:
1. **PLAN FIRST** with the `plan` tool as its first action — an explicit numbered
   list (1,2,3,4,5…) scaled to the task weight, stating done-criteria, the skill
   it will load, the tools it needs, and the verify step. It reacts to each
   observation and re-plans as needed.
2. **Load the matching skill** (`read_skill`) right after planning.
3. **Know & get its tools** — if a needed tool/library is missing, it figures out
   what to install and installs it in the sandbox using the 8-level fallback
   ladder (apt → pip → npm → go → cargo → release binary → container → implement).
   "I don't have that tool" is now an explicit HARD FAILURE.
4. **Do real work, then verify by running** before `finish`.
5. **Never loop / never get stuck** — change approach on failure.

## 3 — Scheduler false-positive bug (two math questions auto-scheduled)  ✅ FIXED + TESTED
**File:** `services/agentScheduler.js`

Root cause: `parseSchedule()` armed a schedule whenever the word "at" appeared
near any 1–2 digit number (so "what is 15 at 3 and 20 at 4", "solve 2+2 and 3+3",
"look at 3 examples" all wrongly scheduled).

Fix — a real intent gate:
- New `_looksNonScheduling()` hard-excludes arithmetic (`\d[+\-*/^=]\d`, "plus",
  "solve", "calculate", …), multi-question batches (≥2 `?`), bare factual
  questions, and code/shell messages.
- New `_hasScheduleVerb()` requires a genuine scheduling/action verb (remind,
  run, check, notify, summarise, send, buy/sell, …) unless the message is
  essentially just a time phrase (`_isBareTimePhrase()`).
- Clock parsing now binds the number tightly to a real cue (`at|by|@` + am/pm or
  `:MM`, or a day word / midnight / noon) instead of any stray "at".

**Test:** `scripts/test-scheduler-falsepositive.js` — **19/19 pass** (11 must-NOT-
schedule cases incl. the exact bug, 8 must-STILL-schedule cases). Existing
`test-scheduler-tz-e2e.js` still 24/24. (The 4 ticker/dispatch failures in
`test-scheduler-e2e.js` are pre-existing — they need Supabase/live timers and
fail identically on the original unmodified code.)

## 4 — Trading price accuracy + smart watch
**File:** `services/manusTools.js` (`getSpot`)

The market-watch ticker's price fetch now **cross-verifies** against an
independent second source (coingecko↔coinbase, gold/crypto↔Yahoo). If the
primary diverges > 2 % from the cross-check, it uses the **median** of the
sources instead of a single possibly-glitched tick — so a bad feed can't fire a
false TP/SL alert. Returns `{ verified, crossPrice }` for transparency.

(The natural-language watch parser already handles TP/SL/above/below/touch +
feedback-only polling; the agent's `watch_market` tool + the 45s poller are
unchanged and continue to alert the instant a level is hit.)

## 5 — Heavy-task hang / no feedback at the peak  ✅ FIXED
**Files:** `services/wormgptBot.js` (Telegram), `services/whatsappBot.js`

Added a **heartbeat watchdog** to both bots. While a task runs it:
- refreshes the "typing" indicator (Telegram) every ~25–30 s, and
- if NO progress note has been emitted for a quiet window (45 s TG / 60 s WA),
  sends a short "⏳ Still working — heavy step running (Ns so far)…" reassurance.

This is exactly the "at the peak it hangs and gives no feedback" case: a long
single step (APK build, big install/scan, slow model call) previously produced
silence. The watchdog is `unref()`ed, self-terminates after a hard cap, and is
cleared on both success and error paths. Env: `BOT_HEARTBEAT_MS`,
`BOT_QUIET_ALERT_MS`, `BOT_HEARTBEAT_MS_WA`, `BOT_QUIET_ALERT_MS_WA`,
`BOT_HEARTBEAT_MAX`.

## 6 — Precise image editing (ImageMagick + Pillow + OpenCV + rembg + FFmpeg)  ✅ ADDED + VERIFIED
**Files:** `agent_worker/bootstrap_tools.sh`, `.codebanana/.skills/precise-image/SKILL.md`,
`prompts/agent_system_prompt.md`, `prompts/skills_index.md`

- New **`precise-image` skill** (indexed as skill #100/105) teaching the agent
  exact, deterministic edits: resize (LANCZOS), crop (exact box), rotate/affine
  (OpenCV), blur/sharpen, grayscale, format-convert/compress, watermark,
  background removal (rembg), image↔video (FFmpeg) — each with VERIFIED commands
  and a mandatory read-back verification step.
- **Bootstrap** gained an idempotent image-toolchain phase
  (`BOOTSTRAP_IMAGE=1`) that installs ImageMagick + FFmpeg + Pillow + OpenCV +
  rembg with the pip-first fallback chain, and verifies each.
- **Routing:** the system prompt now sends EXACT/pixel edits to `precise-image`
  and reserves `edit_image` for creative AI edits.

**Verified end-to-end** (Pillow/OpenCV/FFmpeg present in-sandbox): resize, crop,
blur, rotate, grayscale→JPEG, background-removal pipeline, and image→mp4 all
produced correct output files. ImageMagick + rembg install on the (root) target
sandboxes via the bootstrap.
